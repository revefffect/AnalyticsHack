# Метеоархив · запуск и демо

## Запуск

В каталоге репозитория выполните `docker-compose up --build` или `docker compose up --build`. Откройте [кабинет](http://127.0.0.1:8000). При первом старте загружается архив кейса 02. Доступны демонстрационные кабинеты исследователя и бизнеса. Для Grafana добавьте `--profile grafana` перед `up`. При локальном запуске профиль использует учётную запись Grafana `admin` и пароль `local-demo-grafana`.

В окружении с Python 3.12 и установленными зависимостями:

```sh
python -m pip install -r requirements-dev.txt
METEO_DEMO=1 python -m uvicorn meteo.api:app --host 127.0.0.1 --port 8000
python -m unittest discover -s tests -v
python tools/gap_benchmark.py data/raw/meteo_hack_dataset.zip
```

`METEO_STORAGE` задаёт каталог базы и исходных файлов, по умолчанию это `runtime/`. Приложение раздаёт `meteo/web/` вместе с собранными компонентами. Размер архива — 8,3 МБ, 874 560 строк. Первый выпуск использует SQLite WAL и хранилище исходников на одном постоянном диске. Импорт записывает строки в одной транзакции, отчёт хранит снимок и версию. Для нескольких записывающих реплик потребуется перенос хранилища на PostgreSQL и объектное хранилище. Схема создаётся при старте с номером версии. Будущие изменения схемы оформляются отдельными версионированными миграциями.

## Облачная установка

Используйте один контейнер приложения и постоянный диск. На внешнем прокси терминируйте HTTPS. Перед публикацией задайте `METEO_DEMO=0`, `METEO_ACCOUNTS` как JSON-словарь с отдельными длинными случайными токенами и ролями `research`/`business`, `METEO_FEED_OWNER` и отдельный `METEO_FEED_TOKEN`. Для Grafana назначьте отдельные ключи чтения и записи, настройте URL и `METEO_GRAFANA_OWNER`. Сервисный ключ позволяет читать агрегаты только явно расшаренных наборов этого владельца. Данные источников и отчёты открываются с проверкой прав при каждом запросе. Настройте ограничение входящего трафика и резервное копирование постоянного тома. Ключи передаются через секреты среды.

Внешний HTTPS-приёмник принимает `POST /api/stream/ingest` с токеном и JSON `{id, station, datetime, timezone?, values, qc_flag?}`. Повтор идентификатора с тем же телом не создаёт новую запись. Опоздавшие записи сохраняются по оригинальной дате. Если настроен `METEO_WEBHOOK_URL`, приложение доставляет уведомления POST-запросом из постоянной очереди. Получатель может дедуплицировать по `Idempotency-Key`. Опрос очереди и проверка устаревания идут раз в 15 секунд. Уведомление в кабинете сохраняется в транзакции приёма.

Open-Meteo по умолчанию использует открытый API для проверки и прототипа. Для коммерческого hosted API задайте `OPEN_METEO_COMMERCIAL=1` и `OPEN_METEO_API_KEY`. Реанализ и прогноз сохраняются отдельными типами с моделью, координатами и атрибуцией. [Условия API](https://open-meteo.com/en/pricing) · [Исторический API](https://open-meteo.com/en/docs/historical-weather-api).

## Экраны кабинета

FastAPI отдаёт кабинет по адресу `/`. После входа верхний поиск находит станции и связанные наборы, боковое меню открывает разделы, а переключатель темы меняет палитру всего кабинета. Импорт видит исследователь. Назначенная роль на конкретном наборе определяет, кто может менять его карточку и участников.

| Экран | Что проверить |
|---|---|
| Вход | Открыть кабинет по ключу или выбрать одну из двух деморолей, затем выйти из кабинета. |
| Станции | Найти станцию, сравнить строки реестра, выбрать точку на карте, открыть карточку и перейти к наблюдениям связанного набора. |
| Наблюдения | Выбрать набор, станцию, показатель и период. Сверить график с таблицей, раскрыть исходные строки с флагами QC, скачать срез или сохранить отчёт. |
| Каталог наборов | Найти доступную версию, открыть наблюдения. В окне доступа владелец назначает участника и меняет роль. |
| Загрузить данные | В кабинете исследователя выбрать файл, проверить соответствие полей, применить или сохранить шаблон и подтвердить импорт. |
| Спутник | Выбрать область, продукт и дату UTC. Посмотреть датированное изображение и перейти к источнику обработанных данных. |
| Отчёты | Открыть сохранённый снимок с его периодом, показателем и версией данных, затем вызвать печать. |
| Уведомления | Проверить историю событий. В кабинете исследователя можно также создать правило и воспроизвести архивный поток. |

Веб-интерфейс и автономная демонстрация используют одну оболочку из `meteo/web/index.html` и навигацию из `meteo/web/app.js`. Автономный HTML собирает `tools/build_station_demo.py`, подставляя локальные ответы вместо сервера. Для проверки серверных прав или импорта произвольного файла откройте работающий кабинет. Grafana запускается отдельным профилем Compose.

Таблицы, поля, кнопки и состояния используют общие адаптеры shadcn/ui для нативного HTML. Реестр станций повторяет структуру таблицы Kaggle. Диалог доступа и вкладки реестра используют React-компоненты shadcn/ui на Radix с управлением фокусом и клавиатурой. Оформление задают CSS-переменные в `meteo/web/workspace-shell.css`. Для палитры достаточно изменить их значения, а после изменений JSX требуется пересобрать пакет `frontend/ui`. [Компоненты, реестр MCP и команды сборки](../AGENTS.md#компоненты-интерфейса-и-mcp).

В «Наблюдениях» раскройте «Настроить столбцы», отметьте нужные поля, отредактируйте подписи и измените порядок стрелками. Кнопка «Сохранить вид» записывает настройку для текущего кабинета. Нажатие на период раскрывает исходные строки. Фильтр «Статус наблюдения» показывает, для каких строк есть флаг качества, пустое значение или отсутствующий параметр.

Из открытых шаблонов shadcn/ui ориентирами для таблиц и навигации служат [Tasks](https://github.com/shadcn-ui/ui/tree/main/apps/v4/app/%28app%29/examples/tasks) и [Dashboard](https://github.com/shadcn-ui/ui/tree/main/apps/v4/app/%28app%29/examples/dashboard). Для проверки компонентов выполните `npm --prefix frontend/ui test`. Для сквозной проверки обеих поставок выполните из корня `node --test frontend/workspace-tests/*.test.mjs` с установленными зависимостями из `requirements-dev.txt` и `frontend/ui/package-lock.json`. Переменная `PYTHON` указывает интерпретатор с FastAPI. Для этих команд подходит Node.js 26.

## Карта станций

Откройте «Карта станций» в кабинете или перейдите по пути `/?page=stations&station=KR2`. Нажмите на контур района и выберите АМЕ‑60, Кр1 или Кр2. Карточка показывает площадку, период и число исходных записей в каждом доступном наборе. Нажатие на набор открывает «Наблюдения» с выбранными станцией и версией. Сумма записей в карточке включает каждую доступную версию.

Границы района приблизительны. Научные площадки RU-Fyo и RU-Fy2 показаны отдельными точками по опубликованным координатам. У них можно открыть паспорт и датированные внешние продукты. Для использования в заполнении пропусков проверяйте фактические даты, наличие наблюдаемой температуры и флаги качества. [Описание АМЕ‑60 у заповедника](https://clgz.ru/node/19212) · [RU-Fyo](https://fluxnet.org/sites/siteinfo/RU-Fyo) · [RU-Fy2](https://fluxnet.org/sites/siteinfo/RU-Fy2).

Владелец и назначенный редактор могут добавить фотографию и подпись автора. Фотография доступна читателям этого набора. До загрузки полевого снимка станция получает стабильный векторный аватар с местным ландшафтом. Подложка карты загружается из OpenStreetMap. При недоступной подложке область, координатная сетка, точки и список станций остаются доступны.

[Скачать автономную демонстрацию семи разделов](demo/station-atlas.html). Откройте HTML в современном браузере. В файл включены 6 432 исходные записи архива кейса по температуре и QC для АМЕ‑60 за январь 2010 года, Кр1 и Кр2 за апрель и 1–7 июля 2024 года. Можно проверить архивный пример, посмотреть его разметку, исходные строки и флаги качества, выгрузить срез или создать отчёт. Подложка OpenStreetMap и снимки NASA требуют интернета. Без сети карта сохраняет станции и векторную разметку.

Имена участников и роли в файле демонстрационные. Изменения доступа, правил уведомлений и отчёты действуют в открытой вкладке. Серверный кабинет поддерживает импорт произвольных файлов, доставку уведомлений и общие изменения для нескольких пользователей. Для пересборки установите зависимости из `requirements-dev.txt` и выполните `python -m tools.build_station_demo`.

Для сквозной проверки выполните `npm ci --prefix frontend/ui`, затем `node --test --test-concurrency=1 frontend/workspace-tests/*.test.mjs` из корня репозитория. Проверяются автономный файл, семь экранов мобильного кабинета и ограничения читателя на реальном FastAPI в изолированной базе. При необходимости укажите Python со всеми зависимостями в переменной `PYTHON`.

## Участники и права набора

В каталоге владелец открывает «Настройки и доступ» у нужного набора, выбирает учётную запись и назначает роль. Права применяются к конкретной версии. Для людей используются персональные векторные аватары, для станций — пейзажи.

| Действие | Читатель | Редактор | Владелец |
|---|:---:|:---:|:---:|
| Смотреть наблюдения, источники и фотографии, выгружать срез | ✓ | ✓ | ✓ |
| Менять название и фотографию станции в наборе | | ✓ | ✓ |
| Назначать и отзывать роли, включать общее чтение для авторизованных пользователей | | | ✓ |

Роль кабинета определяет доступ к импорту и управлению источниками. Роль участника задаёт права на выбранный набор. Назначить редактором можно в том числе пользователя бизнес-кабинета. После отзыва доступа к приватному набору его ряды, фото и сохранённые срезы перестают открываться этому пользователю. В режиме общего чтения отзыв роли редактора оставляет право чтения. Исходные наблюдения сохраняются в импортированной версии.

## Спутниковая вкладка

Выберите заповедник, западные или восточные окрестности либо весь район. Вкладка запрашивает датированный слой NASA GIBS. Можно переключать RGB VIIRS, поверхностную температуру MODIS, NDVI VIIRS и тепловые аномалии FIRMS. Пять минут — период запроса интерфейса. Частота поступления спутниковых данных зависит от пролёта, композита и времени обработки. При пропуске сегодня откройте соседнюю дату. Контуры заданы приблизительными прямоугольниками, пока координаты датчиков и границы не согласованы. [NASA GIBS](https://nasa-gibs.github.io/gibs-api-docs/python-usage/) · [FIRMS](https://firms.modaps.eosdis.nasa.gov/content/tutorials/gibs/).

Для признаков по выбранной области доступны ссылки на поиск файлов MODIS и SMAP в NASA CMR. На следующем шаге следует выгружать пиксели и QC по полигонам, сохранять время захвата, версию, долю пригодных пикселей, медиану и перцентили. Sentinel-2 MSI L2A предоставляет атмосферно скорректированные спектральные каналы и SCL. Для мониторинга растительного стресса сравнивайте NDVI/NDMI с сезонным уровнем вместе с влажностью почвы SMAP и осадками. Для пожарной опасности можно сопоставить прогноз FWI с детекциями FIRMS. В этой поставке числовой растр не включается в прогноз модели автоматически. [Sentinel-2 MSI L2A](https://s2.pages.eopf.copernicus.eu/msi/s2msi/main/PDFS_ADFS/L2/PDFS_S2_MSI_L2.html) · [GWIS FWI](https://gwis.jrc.ec.europa.eu/about-gwis/technical-background/fire-danger-forecast).

## Защита за три минуты

1. В кабинете исследователя нажмите «Январь АМЕ‑60». Покажите −15,20 °C за январь 2010, среднемесячное −7,57 °C по 13 пригодным январям и отклонение −7,63 °C.
2. Нажмите «Давление Кр1». На графике месячный показатель пуст, в таблице видны 2/30 суток и 1 272 флага диапазона. Откройте строки с исходными минутами и правилами исключения. Создайте отчёт и выгрузите CSV.
3. В уведомлениях исследователя дважды нажмите «Воспроизвести архив». Первая реальная запись Кр1 выше 20 °C создаёт событие, следующая ниже порога — восстановление. Войдите как бизнес, откройте историю, отчёт из общей выборки и вкладку «Спутник». На отдельном браузере можно сохранить оба кабинета одновременно.

## Границы проверки

Архив, независимые контрольные расчёты, API кабинетов, снимки отчётов, ограничение источника Grafana и повторная доставка потока проверяются локальными тестами. Реальный вход обслуживается по HTTPS после терминации на прокси. В демонстрации для потока воспроизводятся строки архива. Внешние ответы Open-Meteo проверены на фикстуре. Live-запросы провайдеров, контейнер Grafana, пользовательский браузер и облачная установка зависят от среды запуска.

Контракт будущего аналитического агента выдаёт разрешённые `dataset/version`, срез и его QC, источники и события. Вход прогноза хранит дату выпуска, горизонт, провайдера и неопределённость. Генератор PDF использует зафиксированный отчёт и тот же набор чисел. Применение пользовательской видимости выполняется на сервере перед каждым вызовом.

На локальном ASGI-прогоне выборка АМЕ‑60 за 1992–2021 заняла 3,74 с. Запись события в уведомления при воспроизведении заняла 2,18 мс для срабатывания и 1,23 мс для восстановления. Чтение серии потока через тот же API заняло 1,8 мс. Числа относятся к одному прогону. Отдельно требуется замер от приёма записи до обновления страницы Grafana. В демо используются строки 8625 и 8653 файла `data/sokol_m1/kr1_2024.csv`: 1 июля 2024 года в 08:23 — 20,92 °C, в 22:53 — 19,01 °C по часам источника.
