# Источники метеоданных и границы их применения

Архив заповедника содержит показания приборов, у которых сохраняются исходные минуты, флаги и номер строки. Исторический коннектор Open-Meteo получает почасовую температуру модельной ячейки ERA5. Для сопоставления со станцией нужны подтверждённые координаты, часовой пояс и общий период. Часовой пояс архива заповедника остаётся неизвестным.

## Подключение ERA5

Функция `weather.external.fetch_open_meteo` получает модель `era5`, температуру на высоте 2 м, градусы Цельсия и время UTC. Даты включительны. Поддерживается до 366 суток в одном интерактивном запросе. Ответ хранит исходный JSON и его SHA-256, атрибуцию, границы периода, запрошенные координаты, центр выбранной ячейки, высоту, число заполненных часов и дату получения. К каждой строке добавляется указатель на элемент исходного JSON. Ноль сохраняется как измеренное моделью значение, пропуск — как `null`. Число заполненных часов описывает покрытие выбранного интервала. [Исторический API](https://open-meteo.com/en/docs/historical-weather-api) · [Набор ERA5](https://doi.org/10.24381/cds.adbb2d47)

Для повторяемости у среза есть второй хэш `series_sha256`. Он учитывает запрос, координаты ответа, высоту и значения. Длительность выполнения на сервере поставщика может измениться между двумя одинаковыми запросами. При стандартных настройках поставщик применяет коррекцию температуры по высоте. [Описание ответа и выбора высоты](https://open-meteo.com/en/docs/historical-weather-api)

Команда для проверки без ключа в некоммерческом режиме из корня проекта:

```sh
python -c "from weather.external import fetch_open_meteo; r=fetch_open_meteo(56.5,32.9,'2024-04-01','2024-04-01'); print(r['metadata']); print(r['observations'][0])"
```

В коммерческом режиме передайте `commercial=True` и задайте на сервере `OPEN_METEO_API_KEY`. Для Historical Weather API провайдер указывает планы Professional и Enterprise. Коннектор вызывает `customer-archive-api.open-meteo.com` и исключает ключ из метаданных и сообщения об ошибке. На свободном публичном хостинге допустимо некоммерческое использование. Данные распространяются по CC BY 4.0 с атрибуцией и указанием преобразований. Программный код сервера Open-Meteo распространяется под AGPLv3. Эти условия относятся к разным объектам. [Условия хостинга](https://open-meteo.com/en/terms) · [Планы и условия архива](https://open-meteo.com/en/pricing) · [Репозиторий сервера](https://github.com/open-meteo/open-meteo)

Контрольный запрос за 1 апреля 2024 года для тестовых координат 56,5° с. ш., 32,9° в. д. вернул 24 значения в UTC. Центр ячейки — 56,5° с. ш., 33,0° в. д., высота ответа — 260 м. В 00 часов температура составила 12,1 °C, в 23 часа — 10,2 °C. Это тестовая точка. Координаты метеоплощадки таким запросом установить нельзя. [Запрос к архиву](https://archive-api.open-meteo.com/v1/archive?latitude=56.5&longitude=32.9&start_date=2024-04-01&end_date=2024-04-01&hourly=temperature_2m&models=era5&timezone=UTC&temperature_unit=celsius)

## Российские архивы

| Карточка | Что подтверждает владелец | Как получить |
|---|---|---|
| Температура почвы до 320 см | Индекс станции ВМО, дата и 12 глубин с раздельными признаками качества. В паспорте указано продление наблюдений по 2015 год. Поля формата и даты обновления пусты. | Открыть ресурс и описание структуры в паспорте. Если выдача недоступна, владелец указал в карточке контакт. [Паспорт ЕИП](https://eip.meteo.ru/opendata/4025000218-soil320) |
| Радиозондовые наблюдения | ВНИИГМИ-МЦД указывает 12 станций ГСНК, срочные наблюдения и CSV. Актуальность уточняется по запросу. Список идентификаторов станций и период уточняются при получении файла. | В паспорте приведены ресурс, структура и путь в архив ВНИИГМИ-МЦД. При импорте потребуется описание уровней зондирования. [Паспорт ЕИП](https://eip.meteo.ru/opendata/4025000218-aerodata) |

Проверены сведения в паспортах. Файлы этих двух наборов в испытание платформы не входили. В каталоге они помечены как ручное получение. Условия раздела открытых данных ЕИП предусматривают сохранение ссылки на источник и допускают коммерческое использование. Для услуг из отдельного каталога условия уточняются у исполнителя. [Условия открытых данных ЕИП](https://eip.meteo.ru/opendata) · [Каталог услуг](https://eip.meteo.ru/services)

## Какие решения перенесены из опорных проектов

| Задача | Решение для первой версии и основание |
|---|---|
| Каталог | Организация, набор, ресурс и видимость — подходящие сущности CKAN. Для нескольких карточек и выдачи конкретной версии достаточно существующих прав платформы. Отдельная служба CKAN оправдана при федерации каталогов или необходимости совместимого публичного API. [Руководство CKAN](https://docs.ckan.org/en/latest/user-guide.html) |
| Вход со станций | В SensorThings различаются сенсор, наблюдаемое свойство и наблюдение. У WeeWX есть драйверы станций и обработчики архивных записей. Эти решения задают точки подключения будущих приборов. Для воспроизведения одного архива достаточно существующего входа с временем измерения, временем приёма, прибором и идентификатором сообщения. [FROST-Server](https://github.com/FraunhoferIOSB/FROST-Server) · [WeeWX](https://github.com/weewx/weewx) |
| Контроль качества | MADIS описывает уровни и результаты проверок, GHCN-Daily — проверки диапазонов, временных и пространственных связей. В материалах проверки нужно сохранять показатель, правило и причину. Порог из публикации о суточном ряде требует отдельной проверки на наших 15-минутных и часовых сроках. [NOAA MADIS](https://madis.ncep.noaa.gov/madis_qc.shtml) · [Durre и соавт.](https://doi.org/10.1175/2010JAMC2375.1) |
| Восстановление пропуска | В работе Cerlini и соавторов проверялись короткая интерполяция и отдельные методы для длинных разрывов. Lompar и соавторы корректировали ERA5 по данным станции. Для заповедника качество оценивается на скрытых блоках с раздельным результатом по длине и сезону. CSDI описывает вероятностную импутацию, для её оценки потребуются проверка покрытия интервалов и сравнение с простыми методами. [Cerlini и соавт.](https://doi.org/10.1002/met.1913) · [Lompar и соавт.](https://doi.org/10.3390/atmos10010013) · [CSDI](https://proceedings.neurips.cc/paper/2021/hash/cfe8504bda37b575c70ee1a8276f3486-Abstract.html) |
| Прогноз | Сторонний прогноз сохраняет момент выпуска, модель и горизонт. Проверка станционной калибровки проводится на будущих периодах с раздельной ошибкой по горизонту. WeatherBench 2 задаёт воспроизводимый способ оценки глобальных моделей, для локальной оценки нужен отдельный ряд станции. [Калибровка температуры по станциям](https://doi.org/10.1002/met.1971) · [WeatherBench 2](https://research.google/pubs/weatherbench-2-a-benchmark-for-the-next-generation-of-data-driven-global-weather-models/) |
