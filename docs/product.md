# Продуктовый релиз: аналитический пульт «Красное»

Рабочее место для сотрудника заповедника и руководителя, который принимает решение по данным. Один процесс читает архив, считает валидные суточные и месячные агрегаты, хранит экспертную разметку в SQLite и отдаёт интерфейс и PDF.

## Запуск

```sh
python3 -m pip install -r requirements.txt
./run.sh
```

По умолчанию `http://127.0.0.1:8010`. `HOST` и `PORT` переопределяются. Первый запуск строит кэш в `.cache/dataset.pkl`; повторный — читает его. Кэш инвалидируется по версии схемы, размеру и mtime ZIP.

Офлайн-демонстрация:

```sh
RESERVE_OFFLINE=1 ./run.sh
```

Внешний прогноз и внешняя оценка пропусков отключаются, локальные расчёты и PDF работают.

## Что видит пользователь

| Раздел | Ответ |
|---|---|
| Обзор ряда | Что показывает ряд, сколько точек валидно, какое покрытие, отклонение от базы, тренд, где пропуски |
| Качество данных | Покрытие по месяцам, причины исключения, флаги, автоматический EDA, оценка пропуска |
| Риски и прогноз | Прокси пожара, паводка, жары и засухи; статистический прогноз, Open-Meteo, автовыбор модели |
| Экспертная разметка | Ручные отметки эксперта: аномалия, событие, исключение, риск, заметка |
| Отчёт для руководителя | Текст решения, действия, риски, ограничения и PDF |

Клик по точке графика открывает быструю разметку на эту дату. Разметка не меняет расчёт: она попадает в график, список и PDF с именем автора.

## DeepSeek: дашборд словами

`POST /api/ai/dashboard` получает `{prompt, current}`. Сервер отправляет модели каталог станций, параметров, диапазоны дат и текущую спецификацию. Модель возвращает только JSON:

```json
{
  "station": "KR1",
  "parameter": "pressure_hpa",
  "start": "2024-04-01",
  "end": "2024-04-30",
  "granularity": "month",
  "baseline": true,
  "annotations": true,
  "risk_focus": null,
  "title": "Кр1 · давление · апрель 2024",
  "explanation": "Показан апрель 2024, чтобы объяснить исключение давления."
}
```

`validate_spec` проверяет станцию, параметр, диапазон дат и детализацию. Модель не считает числа: после валидации сервер строит ряд, KPI, риски и PDF. Если ключа нет или API вернул ошибку, работает детерминированный русский разбор запроса (`source: "local"`), поэтому демонстрация не зависит от сети.

Настройка:

- `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL` (по умолчанию `https://api.deepseek.com`), `DEEPSEEK_MODEL` (по умолчанию `deepseek-chat`);
- или кнопка «Настроить ключ» в интерфейсе. Ключ хранится в памяти процесса, не пишется на диск.

## Правила расчёта

Реализация повторяет `docs/data-audit.md` и `tools/audit_meteo.py`:

- флаг `параметр:причина` исключает только этот параметр; `dup_conflict` исключает строку целиком;
- сутки валидны при ≥72 различных сроках АМЕ-60 или ≥18 различных часах Сокола для выбранного параметра;
- среднее суток — по всем валидным наблюдениям, включая несколько записей в одном часе;
- месяц валиден при ≤10 неполных днях и максимальной серии <5;
- месячное среднее — среднее суточных средних; многолетнее — равный вес валидных лет;
- пропуск остаётся пропуском: график рвётся, таблица печатает «—», а не ноль.

Контрольные числа проверяются тестами: 874 560 строк, январь 2010 АМЕ-60 −15,20 °C, база 1992–2021 −7,57 °C по 13 годам, апрель 2024 Кр1 +7,61 °C, давление за апрель — 2 дня из 30 и серия 28.

## Экспертная разметка

SQLite `data/annotations.db`. Поля: станция, параметр (или вся станция), период, тип, важность, заголовок, пояснение, автор, время. При первом запуске добавляются три примера, которые можно удалить:

- апрель 2024 Кр1: давление исключено;
- январь 2010 АМЕ-60: −15,20 °C;
- 2016–2017 АМЕ-60: сбой датчика почвы 5 см.

API: `GET/POST /api/annotations`, `DELETE /api/annotations/{id}`. Разметка включается в PDF и в график; в отчёт попадают только отметки текущего параметра и отметки всей станции.

## Интеллектуальный анализ

- Тренд: линейная регрессия по валидным месячным средним, только при ≥24 точках и ≥5 годах. Это описание ряда, не прогноз.
- Аномалии: устойчивое z-отклонение месячного значения от медианы того же календарного месяца (MAD), порог 2,5 σ.
- Риски: процентиль года среди лет архива по метрикам сезона.
  - пожар: летняя температура, сухость, дни «жарко + сухо + ветер», ветер;
  - паводок: морозные дни зимы, скорость прогрева март → апрель, температура почвы весной;
  - жара: летняя температура и число дней ≥25 °C;
  - засуха: сухость воздуха, температура почвы, ветер.
- Ограничение: в архиве нет осадков, высоты снега и влажности почвы. Это управленческие прокси, а не официальный класс опасности. Для Сокола нет почвы, поэтому соответствующие строки доказательств не показываются.

## Прогноз и AutoML

- Статистический прогноз на 6 месяцев: кандидаты «сезонное наивное», «климатология месяца», «линейный тренд», «среднее последних 3 месяцев», «демпфированный сезонный». Выбор по MAE на последних 12 валидных месяцах, интервал 95 % по остаткам.
- Краткосрочный прогноз на 14 дней: климатология дня года + затухающая поправка на последние 14 дней.
- Open-Meteo: 7 дней для точки 56.46, 32.92. Подписан как модель, не измерение. При ошибке показывается причина, статистический прогноз остаётся.

## Оценка пропуска

`GET /api/gap-fill?station=&parameter=&day=`. Если наблюдение валидно, возвращается оно. Иначе:

- климатология того же календарного дня (или месяца), среднее и σ, число наблюдений;
- соседняя точка того же прибора для Кр1/Кр2;
- Open-Meteo archive (реанализ);
- рекомендация: не подставлять оценку в отчёт как измерение и не заполнять ею многолетний тренд.

## PDF

ReportLab + matplotlib. Страницы: решение для руководителя, KPI и график; риски, ограничения, прогноз и бэктест; экспертная разметка и способ проверить число. PDF не содержит выдуманных фактов: текст либо локальный шаблон по рассчитанным данным, либо DeepSeek с тем же JSON-контекстом.

## Демонстрация на 15–20 минут

1. Открыть Кр1, температуру, 2024–2025. Показать +7,61 °C за апрель 2024 и 28/30 дней.
2. Переключить давление на апрель 2024. Показать 2/30, серию 28 и красную экспертную отметку.
3. Ввести «Пожарная опасность на поляне летом 2025». Показать, что DeepSeek/локальный разбор меняет станцию, параметр, период и акцент.
4. Открыть «Риски и прогноз». Показать прокси, ограничения, Open-Meteo и автовыбор модели.
5. Кликнуть по точке, добавить отметку эксперта, открыть «Экспертная разметка».
6. Скачать PDF. Показать решение, риски, разметку и контрольные числа.
7. Открыть «Качество данных» → «Оценка пропуска» для 15.04.2024 давления: климатология, соседняя точка, реанализ и предупреждение.

## Ограничения

- Часовой пояс станций не подтверждён заказчиком.
- АМЕ-60 и Сокол М1 нельзя объединять; тренд через 2021/2022 не строится.
- Риски — прокси, а не официальные классы; для пожара и паводка не хватает осадков и снега.
- Соседняя точка Кр1/Кр2 — не замена: разность точек может быть систематической.
- DeepSeek без ключа не вызывается; локальный разбор покрывает типовые русские запросы, но не свободную форму.
- PDF с кириллицей использует Arial Unicode (macOS) или DejaVu Sans (Linux); при отсутствии обоих ReportLab откатится на Helvetica, и кириллица будет нечитаемой.
