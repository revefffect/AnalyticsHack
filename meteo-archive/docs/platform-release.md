# Метеоархив для исследователей и бизнеса

Защита строится вокруг одного вопроса. Можно ли включить значение в отчёт и проверить, откуда оно взялось? Приложение связывает график с покрытием, флагом, правилом и исходной строкой. В апреле 2024 года станция Кр1 набрала 28 пригодных дней, а давление — 2 из 30. Среднее давления за месяц отсутствует.

## Проверенный сценарий

| Проверка | Результат |
|---|---|
| Импорт полного ZIP в Django | 874 560 записей в трёх версиях. АМЕ-60 — 805 561, Кр1 — 36 544, Кр2 — 32 455. Первый локальный прогон занял около 8 секунд |
| АМЕ-60, январь 2010 | −15,20 °C при 31 пригодном дне из 31 в JSON-выгрузке |
| Кр1, апрель 2024 | 28 пригодных дней станции, 2 пригодных дня давления. Среднее давления отсутствует |
| Импорт форматов | Эквивалентный CSV, XLSX и JSON дают сутки со средней температурой 8,5 °C. Повтор того же импорта сохраняет версию |
| Доступ | Исходник, отчёт и переход в Grafana проверяют доступ к версии. Проверено открытие сохранённого отчёта и блокировка после отзыва доступа |
| Поток | Три записи Кр1 прошли через HTTP. Порог 14,12 °C дал одно срабатывание и одно восстановление. Повторы, запоздавшая запись и устаревание также проверены тестами |
| Задержки | В первом прогоне локальные ответы заняли 4,4–16,5 мс, запись двух событий после приёма — 0,9 и 1,1 мс. Локальный вебхук дважды получил HTTP 204, повторный прогон очереди не создал новых доставок |
| Панель приложения | В повторном прогоне до получения HTML с графиком прошло 127,3 мс при первом запросе и 14,8–15,5 мс при следующих двух. Замер сделан через HTTP под учётной записью получателя и заканчивается получением HTML |
| Open-Meteo | API вернул 24 часа ERA5 для публичной точки в Берлине. Коммерческий маршрут включается ключом провайдера |
| Grafana | Проверены формирование ограниченного токена, доступ при переходе и отказ прокси после отзыва доступа. Docker Desktop в текущей среде не запустился. Совместный прогон Grafana, InfluxDB и Caddy и задержка до панели Grafana остаются открыты |

Архивный поток в демонстрации отмечен как воспроизведение. Время измерения и время приёма хранятся отдельно. У архива неизвестный часовой пояс. Для передачи этих трёх записей используется тестовое допущение UTC с явной отметкой.

## Сценарий защиты на три минуты

1. **0:00–0:35.** Открой каталог станций, выбери урочище «Красное» и Кр1. Покажи импорт и предпросмотр. Отметь выбор колонок и единиц, затем открой подготовленную версию полного ZIP.
2. **0:35–1:30.** Выбери давление и 1–30 апреля 2024 года. Покажи, почему 28 дней работы станции дают только 2 пригодных дня давления. Переключись на сутки и открой 2 апреля. Найди в `kr1_2024.csv` строку 4382, срок `00:02` и флаг `pressure_hpa:range`. Покажи пропуск на графике и то же решение в JSON. При запущенном стенде открой эту версию в Grafana.
3. **1:30–2:10.** Выдай читателю доступ к версии Кр1. В кабинете бизнеса выбери оперативный шаблон, сохрани отчёт и открой печать. Если есть время, открой январь 2010 на АМЕ-60 и покажи −15,20 °C.
4. **2:10–3:00.** Запусти архивное воспроизведение на Кр1. Данные по строкам 8610–8612 — 14,61, 14,57 и 13,67 °C. На 00:36 срабатывает порог 14,12 °C при 30 минутах и двух пригодных замерах, на 01:06 статус восстанавливается. Открой уведомления у получателя и перейди к графику. Покажи, где сотрудник добавляет свою станцию.

## Архитектура и ограничения

Django использует существующую модель каталога, права пользователей и общее расчётное ядро Pandas. HTML и Plotly обеспечивают формы и интерактивный график. SQLite на постоянном томе хранит оригиналы, сжатые нормализованные версии и события. При прогоне трёх версий полного ZIP база заняла примерно 52 МБ. Эта конфигурация рассчитана на один сервер и один экземпляр приложения. При параллельных объёмных импортах стоит отдельно измерить потребность в PostgreSQL и объектном хранилище.

В InfluxDB Grafana получает производные данные. Фоновый процесс создаёт отдельные организацию Grafana и bucket InfluxDB для каждой версии или потока. Он выдаёт токен на чтение одного bucket и синхронизирует агрегаты или новые наблюдения. Caddy передаёт запрос за авторизацией в Django. После изменения прав необходимо повторно открыть доступный дашборд из приложения. Для отчёта по неполному периоду используйте приложение или суточный шаг Grafana. На шагах «декада» и «месяц» Grafana выводит полные периоды внутри диапазона. [Grafana Auth Proxy](https://grafana.com/docs/grafana/latest/setup-grafana/configure-access/configure-authentication/auth-proxy/) · [InfluxDB API](https://docs.influxdata.com/influxdb/v2/api/)

Агрегаты считаются по времени источника. Отдельно видны порог станции, полнота показателя, конфликты и флаги. Вебхук получает стабильный идентификатор события при повторной доставке. Приёмник может распознавать повторы по `Idempotency-Key`. Живой поток требует предоставленного оборудования или сетевого источника. В CSV кейса отсутствуют осадки, поэтому для сценария выбран порог температуры. [Методика SPI](https://www.droughtmanagement.info/standardized-precipitation-index-spi/)

Карточки Росгидромета ведут на официальные каталоги, откуда исследователь может получить разрешённый файл и импортировать его. Условия зависят от продукта. Open-Meteo сохраняет запрошенные и фактические координаты сетки, модель, даты и атрибуцию CC BY 4.0. Бесплатный API проверен для некоммерческого запроса. [Open-Meteo API](https://open-meteo.com/en/docs/historical-weather-api) · [Условия](https://open-meteo.com/en/terms) · [Коммерческие тарифы](https://open-meteo.com/en/pricing) · [ЕИП Росгидромета](https://eip.meteo.ru/services) · [ВНИИГМИ-МЦД](https://meteo.ru/data)

Каталог опирается на модель версий ресурсов и видимости CKAN. Раздельные идентификаторы потока, измерения и времени приёма подходят для будущего адаптера WeeWX или SensorThings. Пороговые проверки и флаги соответствуют подходу MADIS с правилами из кейса. [CKAN](https://docs.ckan.org/en/latest/user-guide.html) · [FROST-Server](https://github.com/FraunhoferIOSB/FROST-Server) · [WeeWX](https://github.com/weewx/weewx) · [NOAA MADIS](https://madis.ncep.noaa.gov/madis_qc.shtml)

## Исследование пропусков

Скрипт строит почасовые средние из пригодной температуры и скрывает непрерывные блоки длиной 1, 3, 6, 12 и 24 часа. Профиль «сезон × час» и поправка соседней станции обучаются на годах перед тестом. Интерполяция оценивает внутренний разрыв до 6 часов при двух доступных концах. Данные Кр1 и Кр2 позволяют проверить поправку по соседней станции с доступными синхронными наблюдениями.

| Метод | Блок | MAE | Смещение | Покрытие |
|---|---:|---:|---:|---:|
| Линейная интерполяция | 1 ч | 0,293 °C | −0,042 °C | 100 % |
| Линейная интерполяция | 6 ч | 1,036 °C | +0,125 °C | 100 % |
| Соседняя станция, Кр1 и Кр2 | 24 ч | 0,746 °C | +0,000 °C | 99,0 % |
| Сезон и час, все три станции | 24 ч | 4,624 °C | +0,115 °C | 100 % |

Для 24 часов MAE на крайних значениях 1,073 °C у соседней станции и 8,521 °C у сезонно-часового профиля. Эти строки относятся к разным множествам станций. Файл `metrics.csv` разбивает результаты по станции, сезону и длине блока. Файл `estimates.csv` хранит экспериментальную оценку, метод, версию и 90-й процентиль абсолютных остатков на обучении для профильных методов. Эксперимент имитирует восстановление уже прошедшего периода. Для прогноза нужен отдельный тест по дате выпуска и горизонту. В пользовательских отчётах остаются пригодные измерения. [Оценка смещения ERA5](https://doi.org/10.3390/atmos10010013) · [WeatherBench 2](https://research.google/pubs/weatherbench-2-a-benchmark-for-the-next-generation-of-data-driven-global-weather-models/)

## Контракты для команды

| Задача | Контракт | Проверка |
|---|---|---|
| Import and quality | Source bytes and confirmed mapping produce an immutable version with QC provenance | Форматы дают одинаковые агрегаты, повтор сохраняет версию, эталоны АМЕ-60 и Кр1 проходят |
| Workspaces and catalog | An authenticated user, an authorized version and report options produce a reproducible report | Фильтр места, приватный набор, доступ с отзывом, исходные строки, печать |
| Grafana, streaming and alerts | An authenticated observation produces a stored point, a scoped dashboard and a durable event | Повторы, опоздания, устаревание, восстановление, доставка, доступ к чужому источнику |
| Validation and release | A clean checkout, a fixture and runtime settings produce a documented release | Миграции, тесты, Compose, источники и трёхминутный показ |

На следующем этапе агент работает от имени сотрудника с теми же правами, что отчёт и выгрузка. Интерфейс чтения принимает `dataset_version`, показатели, даты и шаг, затем возвращает агрегаты, единицы, флаги, метод и ссылки. Запрос прогноза задаёт дату выпуска, горизонт и провайдера. Результат содержит происхождение и неопределённость. Черновик и PDF строятся из зафиксированной сводки со ссылками на исходные строки. Публикация выполняется после проверки сотрудником.
