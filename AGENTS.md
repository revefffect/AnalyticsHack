# AnalyticsHack · правила работы команды

Продолжайте этот репозиторий. Перед изменениями прочитайте [CURRENT_PROMPT.md](CURRENT_PROMPT.md), README, [требования платформы](docs/claude-platform-prompt.md), [контрольные расчёты](docs/data-audit.md) и действующий код своей части. В начале проверьте `git status --short --branch`, `git worktree list` и последние коммиты. Для новой задачи используйте отдельную ветку и отдельную рабочую копию от актуальной интеграционной ветки. В активной работе по платформе интеграционная ветка — `feat/weather-platform`. После её слияния используйте основную ветку.

## Границы работы

| Направление | Область |
|---|---|
| Импорт и QC | `meteo/importer.py`, `meteo/analytics.py`, миграции и тесты расчётов |
| Кабинеты и каталог | `meteo/web/`, пользовательские маршруты в `meteo/api.py`, каталог и отчёты |
| Grafana, поток и алерты | `meteo/stream.py`, `meteo/grafana.py`, `ops/`, тесты потока и изоляции |
| Валидация и выпуск | `docs/platform.md`, `tools/`, интеграционные проверки и конфигурация CI |

Ведите новые задания в GitHub Issues по шаблону из CURRENT_PROMPT.md. В PR или командном канале объявите задачу, ветку и файлы до работы над общими контрактами. Согласуйте изменения маршрутов, схемы хранения, миграций и Compose с владельцами затронутых частей. Добавляйте совместимые поля или новую версию контракта. Применённые миграции оставляйте в истории, а новую нумеруйте после сверки с интеграционной веткой. Обновите тест интерфейса в том же PR. Перед слиянием подтяните изменения коллег и повторите проверки. Если дерево содержит чужие незакоммиченные правки, оставьте их на месте и откройте отдельную рабочую копию. Пушьте свои ветки обычным push. Слияние в общую ветку делает назначенный интегратор.

## Задача Alex и совместная работа

Сначала Alex доводит до рабочего состояния настройку дашборда через DeepSeek, коллективную экспертную разметку и аналитический PDF. Данные и критерии приёмки указаны в [текущем задании на 15–20 минут](CURRENT_PROMPT.md#задание-alex-на-1520-минут). Сквозная отладка инфраструктуры, бэкенда, интерфейса и временных рядов остаётся его следующим приоритетом. В существующем issue он указывает станцию, период или запрос для воспроизведения, ветку и файлы. По инфраструктуре и CI он координируется с Никитой, по API и хранилищу — с Антоном, по интерфейсу — с Анной, по временным рядам, прогнозу и правилам качества — с Кариной.

Если файл уже правит другой участник, договоритесь в том же issue, кто внесёт исправление. Второй участник в это время может воспроизвести ошибку и подготовить проверку. В PR Alex фиксирует, что ломалось до правки и какой результат получен после, с командой проверки или шагами в интерфейсе. Антон координирует слияние по общему порядку.

## Инварианты

- Сохраняйте исходник, версию набора, минуту наблюдения и неизвестность часового пояса. Храните оценки пропусков отдельно от наблюдений.
- Сохраняйте отдельные ряды АМЕ-60, Кр1 и Кр2. Применяйте полевые флаги и правила покрытия из брифа. Используйте один расчёт для таблицы, экспорта, отчёта и Grafana.
- Запускайте `python -m unittest discover -s tests -v`. Для затронутого сценария выполните реальный импорт или воспроизводимый сквозной тест. Передайте команду запуска, фактический результат, SHA и оставшиеся ограничения.
- Держите каждый коммит проверяемым. В теле каждого нового коммита укажите `Оценка проекта: НН/100 (предварительно)`, баллы К₁–К₅ по шкале 0–5, проверенное основание и основной пробел. Веса из README — 7, 4, 4, 3, 2. Оценивайте весь проект на этот коммит и пересматривайте баллы по результатам проверок. Если доступна только копия рубрики, укажите источник.
- Используйте существующие модули и данные. Ключи, базы выполнения и промежуточные выгрузки храните вне Git. Достаточно изменения, которое закрывает согласованный сценарий.

## Компоненты интерфейса и MCP

- Используйте одну оболочку для входа и всех семи разделов кабинета. Разметка и навигация находятся в `meteo/web/index.html` и `meteo/web/app.js`. Общие элементы меняйте у источника, чтобы их получили и динамические формы, и демо. При параллельной работе назначьте одного владельца подключения компонентов в `app.js`, остальные работают в модулях своих экранов.
- Следуйте структуре Kaggle. Размещайте навигацию сбоку, поиск сверху, заголовок над рабочей областью. Подчёркивайте активную вкладку и разделяйте строки таблиц тонкими линиями. Выравнивайте числа по правому краю и указывайте единицы в заголовке столбца. Для показателя с полосой оставляйте видимым числовое значение. [Визуальный референс](https://www.kaggle.com/benchmarks/aisa-group/kaggle-posttrainbench-v1-2/leaderboard).
- Выбирайте существующий компонент по поведению. Вкладки реестра и диалог доступа собраны на React и Radix из `frontend/ui/components/`. Для нативных элементов есть адаптеры паттернов shadcn/ui. `mountUIPrimitives(document)` в `meteo/web/ui-primitives.js` оформляет в том числе динамические кнопки, поля, таблицы и панели. Для выбора значений, флажков и переключателей редактируйте `installFormControls` в `frontend/ui/components/form-controls.jsx`. Сборка обновит `meteo/web/form-controls.js`. Таблицы станций создавайте через `stationDataTable` в `meteo/web/station-table.js`. Сохраняйте связанные подписи, имена полей, доступность с клавиатуры и передачу значений формам.
- Для нового компонента запросите у сервера `shadcn` поиск в стандартном реестре и просмотр исходника. Согласуйте с владельцем экрана, какой существующий модуль расширить. Переносите в него семантику и `data-slot`, связывайте оформление с CSS-переменными темы. Для нового JSX проверьте зависимости и сборку в `frontend/ui/`. В репозитории используется собственный CSS, команды генерации для Tailwind-проекта требуют адаптации.
- В Claude Code и Codex CLI откройте этот worktree и проверьте `/mcp`. В репозитории лежат проектные конфигурации для обоих клиентов. Codex читает такую конфигурацию в доверенном проекте. При первом запуске сервер загружает закреплённую версию CLI через npm. Поиск новых элементов использует сеть. [Сервер shadcn/ui](https://ui.shadcn.com/docs/mcp) · [MCP в Codex](https://developers.openai.com/codex/mcp/).
- Палитры `forest`, `ink` и `violet` задаются в `meteo/web/workspace-shell.css`. Для настройки цвета меняйте `--background`, `--foreground`, `--muted-foreground`, `--border`, `--primary`, `--primary-foreground`, `--accent` и `--ring`, для скругления — `--radius`. Выбор темы сохраняется под ключом `meteo-workspace-theme` в браузере. Поведение меняйте в JSX-компонентах, сохраняя обработку клавиатуры и фокуса Radix. Внешний вид задавайте через имеющиеся CSS и `data-slot`, как у вкладок. При повторном использовании элемента подключайте тот же компонент.
- После правок JSX выполните из корня `npm --prefix frontend/ui ci` и `npm --prefix frontend/ui run build`. После изменений интерфейса обновите автономную версию через `python -m tools.build_station_demo`. Включите изменившиеся результаты сборки и демо в тот же коммит. В затронутом разделе проверьте основное действие при широком и узком окне. При изменениях общих компонентов проверьте обе роли, ввод с клавиатуры, переключение «Реестр / Карта», закрытие диалога через Escape и возврат фокуса. [Экраны и действия для проверки](docs/platform.md#экраны-кабинета).
